# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal Java/Swing project of retirement-planning desktop apps, built via IntelliJ IDEA (not Maven, despite the `pom.xml` — see Build & run) (Monte Carlo withdrawal simulators, Guyton-Klinger guardrails, Social Security optimization, Roth conversion planning). There is no shared framework across the codebase — each package is a largely self-contained, single- or few-file Swing application.

## Build & run

There is a `pom.xml` (Java 25 via `maven.compiler.source`/`target`, single dependency `commons-lang3`), but **Maven is not actually used** — `mvn` isn't installed, and the user doesn't build this way. The real workflow is IntelliJ IDEA: **Build > Rebuild Project**, then **Build > Build Artifacts** (see `.idea/artifacts/IncomeLab_OptSocSec_v8_jar.xml`) to produce the jar. `target/maven-status` and `target/maven-archiver` are stale leftovers from an old Maven-based setup — ignore them, don't treat their presence as evidence Maven is in use.

From a shell, verify compilation with `javac` directly (see below) rather than reaching for `mvn`.

There is no `src/test` directory and no test suite.

### The active application

The actively developed app is:

```
src/main/java/com/hiflite/incomelabs_riskbased/IncomeLab_OptSocSec_v8.java
```

- This is the `Main-Class` in `src/main/resources/META-INF/MANIFEST.MF` and the class referenced by the IntelliJ artifact config `.idea/artifacts/IncomeLab_OptSocSec_v8_jar.xml`.
- It has zero imports outside `javax.swing`/`java.*` (no `commons-lang3` usage), so it compiles standalone: `javac -d out src/main/java/com/hiflite/incomelabs_riskbased/IncomeLab_OptSocSec_v8.java` (verified working), then run with `java -cp out com.hiflite.incomelabs_riskbased.IncomeLab_OptSocSec_v8` (no CLI args; opens a Swing GUI).
- `src/main/java/com/hiflite/Main.java` is unrelated IntelliJ scaffold boilerplate, not the app entry point.

### Version history pattern

`incomelabs_riskbased/` contains successive versions of the same app: `IncomeLab_OptSocSec_v4.java` through `v8.java` (older ones like v2/v3 have been deleted from the working tree). **Always work in the highest-numbered `vN` file** — earlier versions are kept only as history/reference, not maintained. When bumping to a new version, follow the pattern already established in the file header of `v8.java`:
- Copy the file, increment `APP_VERSION` and rename the class/file.
- Update the `BUILD_STAMP` constant near the top of the class to the current date/time — it's surfaced in the window title and is expected to stay in sync with the "Last modified" comment on line 3 of the file.

### Other packages are AI-authored exploratory alternates — not actively developed

Every other top-level package under `src/main/java/com/hiflite/` is a separate, independent exploration of similar retirement-simulation ideas (Guyton-Klinger guardrails, Monte Carlo withdrawal modeling), largely generated by different AI assistants and named accordingly:

- `boldinguardrails_claude/`, `montecarlo/claudeai/` — Claude-authored
- `guyton_klinger_gemini/`, `modernGuardrails_gemini_v2/`, `modernguardrailsmodel_gemini/` — Gemini-authored
- `riskbasedguardrails_grok/` — Grok-authored
- `montecarlo_excel_unfinished/` — incomplete port of an Excel-based model

These are independent, each with its own `main()`, not part of the `incomelabs_riskbased` app and not imported by it (aside from shared bits in `utils/`). Treat them as reference/scratch material unless the user is explicitly working in one of them — don't assume changes there affect the main app, and don't pull the main app's conventions into them (or vice versa) without being asked.

`src/main/java/com/hiflite/utils/` has small shared helpers used across packages (`SocialSecurityBenefitCalculator`, `TimingUtils`, `CsvStyles`).

## Architecture of `IncomeLab_OptSocSec_v8.java`

The whole app is one `JFrame` subclass with static inner classes for data/results. Read the class-level Javadoc at the top of the file (`== METHODOLOGY ==` section) before making simulation-logic changes — it documents the withdrawal-solving algorithm in detail. Summary:

- **Two-level withdrawal engine**: an inner Monte Carlo loop (`survivalRatePro`) simulates a fixed real-dollar withdrawal schedule over the horizon for a candidate first-year withdrawal; a middle binary search (`solveWithdrawalPro`) finds the withdrawal that hits the target probability of success; an outer loop re-solves annually along each fan path using the 50th-percentile balance, so the displayed schedule adapts year to year even though inner trials don't re-optimize.
- **Tax engine** (`TaxEngine` inner class, with `StateTaxProfile`/`StateTaxYear`): federal + state + IRMAA computed on the Pro PoS median path, with per-year state tax rules keyed by a `year -> StateTaxYear` map (`floorEntry` lookup) so historical/future rule changes are data additions, not code changes. Roth conversions are modeled as a separate taxed Traditional distribution that raises MAGI but is excluded from the living-expenses Tax column.
- **UI is tab-based** (`mainTabs`, a `JTabbedPane`), built in the constructor: Pro PoS Table, Guyton-Klinger (Option C), Simulation Chart, Summary, SS Optimizer, Stress Test, Assumptions & Methods. Each tab has a corresponding `buildXPanel()` method.
- **Scenario persistence**: user inputs save/load as `.ilscen` files via `JFileChooser`, under `~/.retirement_utils/.incomelab/scenarios/` and `~/.retirement_utils/.incomelab/calibration/` (not under the repo). `recent.ilscen.prefs` and `calibration.ilscen.prefs` inside the calibration dir track recently-used files. `SavedScenarios/` at the repo root is effectively unused (empty) — real scenario files live outside the repo, under the user's home directory.
- Key inner classes: `SimInputs` (user inputs), `ProResults`/`EnhRow` (per-year simulation output rows), `SsOptResult` (Social Security optimizer output), `GkRow`/`GkResults` (Guyton-Klinger tab), `TaxEngine`/`TaxResult`, `HistoricalScenarios`, `SeededRng`.

## Notes

- `src/main/java/com/hiflite/montecarlo/claudeai/RothConversionPlanner.java` declares `package com.hiflite.incomelabs_riskbased;` despite living under the `montecarlo/claudeai` directory — a pre-existing directory/package mismatch. It still compiles (javac/Maven use the package statement, not the directory, to place the class), but don't assume the file's directory tells you its package, or vice versa, when searching this one file.
- `qodana.yaml` configures JetBrains Qodana static analysis (`qodana.starter` profile, JDK 25) — not wired into a CI pipeline in this repo, just available for local/manual runs.
- CSV outputs (`Retirement_Full_Report.csv`, `Retirement_Simulation_Results.csv`) and `out/` at the repo root are simulation run artifacts, not source — safe to ignore/regenerate.
